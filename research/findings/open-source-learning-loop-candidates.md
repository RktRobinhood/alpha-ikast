# Open-source candidates for the first AA SL learning loop

**Question:** Which additional maintained open-source projects could support a self-hosted AA SL learning loop, especially a low-stakes baseline exploration at first sign-in and inline prerequisite support for function notation, composite functions, and inverse functions?

**Status:** focused primary-source investigation, 2026-09-05. This is a reuse and trial recommendation, not an architecture selection or legal advice.

## Boundary for this comparison

The first sign-in experience is a **baseline exploration**, as defined in [CONTEXT.md](../../CONTEXT.md): it samples a broad collection of developed or adopted topics at and below the learner's expected course level, is low stakes, and routes to named prerequisite support while preserving the current AA SL destination. For the next unit, that means a short sample spanning function notation/composition/inverses and introductory quadratic work.

The [licensing strategy](../synthesis/licensing-strategy.md) applies to every recommendation below. A source-code licence permits only the code it covers. Each adopted question, image, video, or textbook-derived item needs its own recorded provenance, exact source revision, licence, attribution, modification state, and AA SL competency tags. A GitHub fork is technically possible for public repositories, but copying, adapting, or redistributing is justified here only where the upstream licence grants those rights and its conditions can be met.

## What this means for the resource-preparation concern

Resource preparation should start **before** a broad content pull. The first asset is a small, inspectable competency-and-provenance catalogue, not a large copied library.

For each first-loop activity, record:

1. the learning-horizon and competency/prerequisite identifiers;
2. whether it is an independent probe or guided practice;
3. the exact engine and authoring source, upstream revision, code licence, and content licence/attribution;
4. the response fields, deterministic marking/feedback rules, and event fields required for the learner state;
5. browser/device and accessibility checks; and
6. a teacher review of mathematical validity, notation, AA SL relevance, and the route offered after each result.

For the initial baseline, use only a few validated items. It should be short enough that it works at first sign-in, while branching on independent evidence for function notation, composition/inverses, algebraic rearrangement and early quadratic understanding. A student who needs function-notation support should enter a brief Numbas adaptive/guided activity, then return to the shared quadratic destination. That preserves teacher steering and keeps the baseline separate from a high-stakes placement test.

## Recommended validation sequence

1. Fork the three Apache-licensed Numbas repositories above on GitHub, with their original notices intact and a recorded upstream SHA. Do **not** import third-party Numbas exam content without its individual licence and provenance.
2. Author or adopt under an explicit licence a six-to-eight-item Numbas baseline: two function-notation items, one composition/inverse item, two algebra/form items, and two introductory quadratic items. Keep the baseline algorithm simple initially; export only the response events required for later learner-state comparison.
3. Build two inline prerequisite supports in the same engine: interpreting `f(x)`/substitution and inverse/composition notation. Each should return the learner to an introductory quadratic function/equation activity.
4. Run a small STACK/Moodle comparison on equivalent items. Compare authoring time, correctness/feedback for expressions and required form, teacher review/reporting, mobile/browser behavior, event extraction and operating burden.
5. Decide later whether to retain Numbas as the activity engine, use STACK for selected server-side items, or introduce an LMS shell. Neither choice should make an external engine the system of record for the learner state.
